Retrieval

No second store

A knowledge base is easy to write into and hard to read out of. The retrieval layer is made of rules rather than machinery: nothing is generated, nothing has to be rebuilt. What changes is only when things happen in a session.

What every active note carries

  • A summary: line of at most 160 characters
  • Purpose and scope only, never state. No version numbers, no test counts, no status
  • A sentence about purpose does not go stale when the work moves on

A hub links its own sub-files

  • A note nobody links to is found only by accident
  • Creating a sub-file means adding it to the hub in the same move
  • vault-inventory checks it, and repairs nothing

Why there is no index in front of it

  • A full-text scan of the whole vault took 53 to 118 ms
  • A generated index of the same vault weighed 48,509 characters, loaded every session
  • That answer flips past a few hundred notes. The point is to measure rather than assume

Strip code blocks and backticks before checking links. A naive scan returned 27 dead ones, and not a single one was real.
