Architecture

One rulebook, any agent

Four coding agents read four different entry files. All four entry files say the same three lines: read AGENTS.md. Everything below the rulebook is either the vault it governs or a mirror generated from a single source.

Why the adapters stay empty

  • CLAUDE.md and GEMINI.md are three lines each: read AGENTS.md
  • Codex and OpenCode read AGENTS.md natively, so they need no adapter at all
  • A rule written twice is a rule that will disagree with itself

Why the skill folder is mirrored

  • Claude Code and Codex only discover skills inside their own folder
  • Gemini CLI and OpenCode read skills/ directly, because the rulebook tells them to
  • Third-party skills pass a security gate first, one at a time, then land in skills/

How it gets there, and stays there

  • SETUP.md is an installer written for an agent, not for a human. Re-running it only ever adds
  • Every session: pull, triage the inbox, write the daily note
  • Every month, twice: an environment check and a content inventory

The one rule underneath all of it: information has exactly one home. Everything above is a consequence of that.
